# H5直播模块选型与首版边界

2026-11-09。用户确认直播是核心功能；先完成现有业务，再实现直播。优先轻量、自部署和低成本，带宽扩容后续处理，不作为开始开发的阻塞。

## 候选比较

| 候选 | 适用点 | 首版取舍 |
|---|---|---|
| MediaMTX | 浏览器WebRTC发布/播放、HLS、外部HTTP或JWT鉴权 | 首选验证，单主播广播不必引入会议模型 |
| SRS | RTMP/WebRTC/HLS直播媒体服务 | 备选，遇到协议兼容或运维问题再评估替换 |
| LiveKit | WebRTC房间和多端SDK | 多人连麦候选，首版没有连麦需求，暂不引入额外房间体系 |

这是集成复杂度判断，不是相同负载的性能或成本实测。

## 初步方案

现有Vue H5增加一级直播菜单。Java单体继续负责账号、组织、角色、房间元数据和配额；独立MediaMTX容器只处理媒体。复用现有MySQL，不另建业务项目、不引入独立登录平台。首版单主播、单清晰度，不转码、不默认录制，降低资源和存储开销。

直播管理：创建、编辑标题/封面、停用、观看权限、复制分享链接；主播页明确点击后申请摄像头及麦克风，WebRTC推流；观看页通过独立分享ID查房间并取短期观看授权。分享ID不是推流凭据，组织与主播权限由服务端校验。默认组织内观看，公开分享需显式开启。

采用房间与直播场次两层，房间可复用，每次开播独立session。创建/开播/结束请求幂等，媒体在线状态由媒体回调或服务端核对，不能仅凭前端按钮标为正在直播。媒体凭证短期、绑定路径与publish/read权限，禁止前端拿到服务器管理密钥；跨组织查询/开播拒绝。

手机浏览器编解码、摄像头切换、静音、断线提示和重连需实际验证。优先WebRTC观看；HLS仅在编码兼容验证通过后启用，不承诺任意浏览器发布流都可直接转HLS。

现有SSH/HTTP隧道只能解决信令入口，不能假定WebRTC媒体自动穿透。验证阶段应明确公网ICE路径以及需要时的TURN中继，部署前单独审查端口，不自动修改防火墙或受限隧道账号。带宽参数独立配置；不因带宽尚未扩容而阻挡房间业务开发。
