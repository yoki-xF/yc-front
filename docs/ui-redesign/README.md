2026-11-05，用户选择：蓝白、清爽专业、账目清晰。范围是同一个原生微信小程序中的员工、老板、平台管理。直播暂不加入本轮导航；后端保持单体，不改变账务口径。

## 当前问题与重组

- 员工首页在一张卡片中连续堆放销量、十几个操作和账号按钮；主要任务缺少层级。拆成门店范围、营业任务、单据、销量、个人入口。
- 老板工作台把管理目录、报表与结店平铺。经营概览、营业管理、记录查询、团队设置分别聚合；高风险动作留在详情核对页。
- 后台按历史模块名称展示；同一底层页面承载多个业务类型。用户可见入口按业务任务命名，动态路由和原权限继续保留。
- 不引入没有接口的数据：待办数量、营业中实时销量、跨店资金汇总、平台客户健康指标必须来自真实授权接口。接口暂缺时显示“待读取/暂无已结店报表”，不能把原型数字接成产品常量。

## 导航与角色

建议四个稳定底部入口：**工作台 / 单据 / 报表 / 我的**。角色及门店切换放在顶部范围栏，平台管理从有权限账号的角色选择进入。没有某项权限时移除相应动作；仍可保留稳定顶级入口并显示准确空状态，不能只用界面角色代替后端鉴权。

| 模式 | 工作台重点 | 单据 | 报表 | 我的 |
| --- | --- | --- | --- | --- |
| 员工 | 门店、营业日期、早盘/记账/晚盘/资金盘点、盘点进度 | 即开票采购/调拨及状态、备付金转入 | 我的电彩/竞彩；门店即开和已结店汇总独立展示 | 个人资料、消息、手册、客服、退出 |
| 老板 | 门店范围、开店/结店、初始化入口、经营管理 | 营业记录、凭证、成本、盘点及留痕更正 | 日/周/月、门店总量与资金账差、个人销量排名 | 团队/角色、排班、经营设置、账号资料 |
| 平台管理 | 有权限模块分组；客户与套餐、账号权限、门店配置、通知、日志 | 授权库存及单据查询 | 仅已有授权报表；不虚构平台经营总览 | 组织设置、账号、安全、帮助 |

原型中切换角色是演示工具；正式角色切换须基于服务器权限响应。平台账号不是默认具备所有租户营业数据访问权。客户/套餐等 `platformOnly` 功能必须继续要求平台管理员。

现有49个注册页面、40个后台入口和9个老板模块全部映射在 [page-map.json](page-map.json)。这是设计覆盖，不是49个页面已改造的证明。支付页面映射为暂缓；旧消息管理页按具体 type 分别保留站内信/禁用短信邮件社交。

## 核心流程与页面布局

1. **进入门店**：账号密码 → 可选门店 → 营业日状态。无门店、无权限、营业日未开分别给出下一步。无公开注册/短信登录。
2. **营业任务**：开店由有权限的人操作 → 早盘 → 营业记账 → 晚盘/资金核对 → 有权限的人结店。卡片展示实际状态，不凭本机时间或 UI 顺序推断已完成；跨午夜仍显示开店当天。盘点是否可操作由服务端校验，不在 UI 发明新的先后强制关系。
3. **资金盘点**：门店和营业日固定在顶端；五类资金为五组，每组金额与可选笔数靠近；草稿/版本冲突/结果不明独立状态；核对页列出五类金额、影响和提交对象，再确认。仅缓存草稿，不重试财务 POST。
4. **即开单据**：采购/调拨分组；列表保留类型、门店、日期、金额、状态；详情才显示确认/撤销等有权限动作。两店调拨确认仍校验接收门店，不能一键批量绕过。
5. **报表**：先选择门店、日期与日/周/月，再区分已结店数据/待生成/更正后待重核；个人区只显示电彩与竞彩，门店区显示即开和门店盈亏。金额右对齐，标签与单位完整。资金账差不是会计利润，不能改叫“净利润”。
6. **结店核对**：五类期初/期末、三类销量、调整项、备付金和单列错票；预览版本过期要求重新读取；正式按钮为“确认核对并结店”。
7. **更正**：原记录只读 → 可改字段 → 必填原因 → 影响范围 → 确认更正 → 审计记录与报表重核状态。不得退回“编辑后直接覆盖”。
8. **团队**：账号列表 → 详情 → 角色/门店/岗位；停用代替删除，保护本人账号与历史关联；密码重置单独确认，不把明文写到列表或操作日志。
9. **平台管理**：客户与套餐、账号岗位权限、菜单字典公告、库存门店配置、站内信、访问/错误/操作日志分组；动态表单使用统一列表/详情/编辑壳层。敏感配置仅写入、不回显。第三方功能不出现在日常分组。
10. **保留业务**：促销活动归营业，返佣归经营记录，排班考勤归团队；不因界面精简删除。导入/导出保留权限、私密文件清理与长 ID 保护。

## 视觉与组件规范

蓝色 `#0052D9` 仅表示主操作/选中；正文 `#172B4D`，次要文字 `#52647C`，底色 `#F4F7FC`，白色表面。成功 `#157347`、警告 `#805300`、错误 `#B42318`，必须有文字，不能只看颜色。

- 8px 间距体系；左右16px，卡片16px内边距、12–16px圆角。不使用大面积渐变或装饰图。
- 正文16px，标题20–24px，金额24–32px；辅助说明不低于14px。原生实现按750设计宽度换算 rpx，文字放大时布局自然换行。
- 触控区域至少44px；一屏一个主要操作。金额采用等宽数字、右对齐；输入保持金额文本，不用浮点 Number 重算。
- 列表每项主标题/范围/状态/金额，低频操作放详情；字段多的管理端不要横向压缩成手机表格。
- 共用范围栏、分段选择、状态标签、加载/空/错误、业务卡片、金额字段、底部提交栏；业务组件只负责显示/事件，不持有新的全局会话或替代服务权限。
- 安全区与键盘避让；底部栏不遮字段和错误。长门店名、19位ID、大金额、窄屏和大字号必须验证。
